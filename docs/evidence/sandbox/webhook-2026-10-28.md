# PayPal webhook, verified end to end (Oct 28, 2026, hosted demo at commit 1f96b91)

PayPal sends refund and dispute events to `https://agentcosign-demo.onrender.com/v1/webhooks/paypal`. The server trusts an event only after PayPal's own `verify-webhook-signature` answers `SUCCESS` for our webhook id; anything else is refused before it is read.

| Step | Result |
|---|---|
| Webhook registered on the sandbox app, read back from PayPal | URL above; events: capture refunded, capture reversed, refund failed, dispute created, updated, resolved |
| Events PayPal generated for our refunds (`GET /v1/notifications/webhooks-events`) | 3 `PAYMENT.CAPTURE.REFUNDED` events since registration, one per refund (`509243129D3920541`, `2RR7029644429264V`, `6YB708398H1220608`) |
| PayPal asked to re-deliver the real event for `6YB708398H1220608` (`POST /v1/notifications/webhooks-events/{id}/resend`) | PayPal: 202 accepted |
| Hosted server log | `POST /v1/webhooks/paypal HTTP/1.1" 200 OK`: signature verified by PayPal, event accepted |
| Public record head (`/api/v1/audit/head`) | entry 1 before the resend, entry 2 written seconds after (13:02:14 UTC): the event is in the signed record |

## A fake event is refused

| Step | Result |
|---|---|
| PayPal's Webhooks Simulator sent a mock `PAYMENT.CAPTURE.REFUNDED` (dated 2014, a $0.15 refund that never happened) to the same URL, 18:38 IST | queued by PayPal |
| Hosted server log | `POST /v1/webhooks/paypal HTTP/1.1" 400 Bad Request` twice (the delivery and a retry): PayPal's check did not verify it, so it was refused unread |
| Public record head | still entry 2, same hash: the fake event changed nothing |

PayPal states that simulator events cannot be verified; the server treats anything PayPal does not verify as untrusted. The same path is covered offline by the webhook tests in `tests/unit/test_gateway_api.py`. Note: only the host's live log was checked; PayPal's first delivery of that event on Oct 27 was not looked up. The resend shows the full path working.
